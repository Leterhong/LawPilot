## 二、法律法规条文

### 2.1 字段结构

```json
{
  "law_name": "中华人民共和国民法典",
  "chapter": "第一编 总则",
  "section": "第六章 民事法律行为",
  "article": "第143条",
  "content": "具备下列条件的民事法律行为有效：……",
  "keywords": ["民事法律行为", "..."],
  "effective_date": "2021-01-01",
  "status": "现行有效",
  "source": "全国人民代表大会"
}
```

`chapter` / `section` 保留条文在法典中的层级位置，使检索结果能回溯到章节上下文而非孤立条文。

### 2.2 颁布机关分布（实测）

| 颁布机关 | 条数 | 占比 |
| --- | --- | --- |
| 全国人民代表大会 | 451 | 51.7% |
| 全国人民代表大会常务委员会 | 402 | 46.1% |
| 国务院 | 9 | 1.0% |
| 最高人民法院 | 8 | 0.9% |
| 住房和城乡建设部 | 2 | 0.2% |

### 2.3 法规覆盖（Top 10）

| 法规 | 条数 |
| --- | --- |
| 中华人民共和国民法典 | 294 |
| 中华人民共和国刑法 | 92 |
| 中华人民共和国民事诉讼法 | 29 |
| 中华人民共和国刑事诉讼法 | 21 |
| 中华人民共和国劳动合同法 | 20 |

| 中华人民共和国行政强制法 | 10 |

覆盖 132 部法规，集中在与普通人维权最相关的领域（民事、劳动、消费、合同）。

### 2.4 生效日期分布

- 最早：1980-09-10（《中华人民共和国刑法》原始版本）
- 最晚：2024-07-01（《中华人民共和国公司法》2023 修订）
- 全部 872 条均带有 `effective_date` 与 `status` 字段

### 2.5 采集与校验方式

- **采集**：依据国家法律法规数据库（flk.npc.gov.cn）公开条文人工整理，按"法条"粒度切分为 JSON Lines
- **校验**：逐条比对条文原文，保留章节归属；`source` 字段记录颁布机关
- **未使用**：未使用爬虫批量抓取，未使用模型生成条文内容

> **重要声明**：本数据集为**演示用种子数据**，不是全量法律数据库。系统检索能力的上限由该数据集决定，生产环境须对接权威数据源（如国家法律法规数据库官方接口或商业法律数据库）。

## 三、司法案例

### 3.1 数量与来源

- **29 条**，全部来自**最高人民法院指导案例**
- 文件：`backend/sample_data/legal_cases.jsonl`

### 3.2 字段结构

```json
{
  "title": "指导案例1号：上海中原物业顾问有限公司诉陶德华居间合同纠纷案",
  "case_number": "指导案例1号",
  "court": "上海市第二中级人民法院",
  "province": "上海",
  "city": "上海",
  "trial_date": "2010-10-21",
  "case_type": "contract",
  "court_level": "intermediate",
  "cause_of_action": "...",
  "plaintiff": "...",
  "defendant": "...",
  "facts": "...",
  "court_reasoning": "...",
  "judgement": "...",
  "winner": "...",
  "compensation": "...",
  "keywords": ["..."],
  "related_laws": ["..."],
  "source": "最高人民法院指导案例"
}
```

保留了 `facts` / `court_reasoning` / `judgement` 三段式结构，使检索可以命中"裁判要旨"而不只是案由标题。

### 3.3 为什么选择指导案例

指导案例由最高人民法院统一发布，具有**参照效力**，是唯一可以安全地在产品中向用户展示"类似案件法院怎么判"的案例类型。普通裁判文书存在地域差异与说理质量参差，不适合直接推荐给不懂法律的用户。

## 四、案由知识模板

**来源**：人工编写，基于《民事案件案由规定》与常见法律援助场景整理。

包含 8 类案由，每类含：

| 内容 | 用途 |
| --- | --- |
| 追问脚本（3-5 个问题 + 快捷选项） | Agent 逐条收集事实的结构化输入 |
| 建议证据清单 | 报告"建议准备证据"章节 |
| 权益分析模板 | LLM 不可用时的兜底正文 |
| 对方可能存在的问题 | 同上 |
| 推荐办理部门 | 报告"去哪里"章节（劳动仲裁委 / 12315 / 住建局等） |
| 可用文书类型 | 报告"可自动生成文书"章节 |
| 风险要点 | 诉讼时效、举证责任等提示 |

**定位说明**：这是**兜底与约束**，不是最终输出。配置 LLM 后，正文由模型基于用户个案事实生成，模板退居为"防幻觉底线"与"字段完备性检查表"。

## 五、AI 生成内容的边界

这是法律类产品最需要说清的部分。

| 内容类型 | 是否由 AI 生成 | 说明 |
| --- | --- | --- |
| 法条原文 | ❌ 否 | 来自人工整理的种子数据，模型只负责检索与引用 |
| 法条编号 | ❌ 否 | 引用编号由系统分配，模型越界即作废 |
| 案例原文 | ❌ 否 | 来自最高法指导案例，不做改写 |
| 案件分析 | ✅ 是 | 基于用户陈述 + 检索法条生成，受三道闸门约束 |
| 法律文书草稿 | ✅ 是 | 用户需自行核对后使用 |
| 追问问题 | 部分 | 配置模型时由模型生成措辞，未配置时用脚本固定文案 |

### 三道防幻觉闸门

1. **事实封闭**：模型只能使用用户亲口陈述的内容，Prompt 中显式禁止臆测
2. **法条封闭**：只能引用传入编号（`【法条1】` 至 `【法条N】`），系统正则校验，越界即整份作废
3. **结构可校验**：强制 JSON，五字段非空校验，超长截断

任一道不通过 → 回退规则模板 → **报告永不为空，永不报错，永不出现编造法条**。

验证代码：`backend/tests/test_llm_report.py`（13 个用例，含引用越界、JSON 破损、模型超时、无密钥等降级路径）

## 六、Embedding 与向量数据

| 项 | 说明 |
| --- | --- |
| 模型 | BGE-M3（可配置，默认 1024 维） |
| 存储 | PostgreSQL + pgvector，`legal_reference.embedding` / `legal_cases.embedding` |
| 生成时机 | 灌库脚本 `backend/scripts/ingest_knowledge.py` 批量生成 |
| 更新策略 | 法条变更后需重跑 `backfill_embeddings.py` |
| 降级 | Embedding 服务不可用时自动退化为纯关键词检索，响应标记 `used_hybrid=false` |

**说明**：Embedding 是法条的向量表示，不引入外部知识，因此不构成新的数据来源风险。

## 七、隐私与合规

### 7.1 用户数据

| 数据 | 存储 | 保护措施 |
| --- | --- | --- |
| 账号密码 | PostgreSQL | bcrypt 哈希（加盐，不可逆） |
| 案件描述、对话记录 | PostgreSQL | 按 user_id 隔离，接口层强制鉴权 |
| 上传证据（图片/文档） | 容器卷 `uploads` | 按案件隔离，取回需鉴权 |
| 模型 API Key | PostgreSQL | Fernet 对称加密存储，密钥由 SECRET_KEY 派生 |

### 7.2 对外传输

- 仅将**必要文本**发送至模型服务（案情事实 + 检索到的法条），不发送用户身份信息
- 不将证据原件上传至模型服务
- 模型服务商的选择由部署方决定，建议签署数据处理协议

### 7.3 AI 生成内容标识

报告页顶部明确标注生成方式（「AI 个性化分析」/「规则模板生成」），符合《生成式人工智能服务管理暂行办法》关于生成内容标识的要求。

## 八、已知局限（主动披露）

1. **数据规模**：872 条法条不足以覆盖全部法律咨询场景，仅覆盖 132 部法规中的常见条文。用户问到未收录领域时，系统会明确回复"暂未检索到高度相关的法律条文"，而不是编造。
2. **时效性**：法条有修订与废止。系统保留 `effective_date` 与 `status` 字段，但**尚无自动更新机制**，需要人工定期核对。这是生产化的必要投入。
3. **地域差异**：地方性法规、地方司法实践差异未覆盖。
4. **案例规模**：29 条指导案例数量有限，"相似案例"推荐的代表性不足。
5. **非法律意见**：系统输出为办事参考，不构成法律意见，不替代律师判断。此声明在每份报告末尾固定展示。

## 九、数据可复现性

任何人可执行以下命令核验本文档中的数字：

```bash
cd backend
# 法条总数
cat sample_data/laws*.jsonl | wc -l

# 覆盖法规数
cat sample_data/laws*.jsonl | python -c "
import json,sys
print(len({json.loads(l)['law_name'] for l in sys.stdin if l.strip()}))
"

# 案例数
wc -l < sample_data/legal_cases.jsonl

# 颁布机关分布
cat sample_data/laws*.jsonl | python -c "
import json,sys,collections
c=collections.Counter(json.loads(l)['source'] for l in sys.stdin if l.strip())
[print(v,k) for k,v in c.most_common()]
"
```
