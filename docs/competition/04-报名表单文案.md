## 一、赛题方向

**选择：AI+民生服务类**

理由：明路的服务对象是遇到欠薪、押金、消费维权等高频小额纠纷的普通人，产出是「该找谁、带什么材料、多久内办」的办事路径，属于典型的普惠型民生服务，不是产业侧工具、不是底层技术、也不是消费娱乐。

不建议的选项：
- AI+产业发展类：产品不与具体产业链绑定，硬靠会显得牵强
- AI+原生技术与科学创新类：技术路线是工程组合（pgvector + RRF + 引用校验），不是新算法
- AI+数字治理与生态协同类：可作为第二落点（社区法律服务点、普法），但主体仍是民生
- AI+消费提质与文创新消费类：易被理解为消费内容产品，与法律服务属性不符

## 二、项目描述

### 1. 项目简介（不少于 200 字）

明路（LawPilot）是面向普通人的 AI 法律办事助手，把一段说不清楚的纠纷遭遇，整理成一条可以照着走的办事路径。用户遇到欠薪、租房押金、消费维权、借贷、婚姻、医疗、快递物流等 8 类高频日常纠纷时，最先想知道的往往不是法条原文，而是我现在该找谁、要带什么材料、多久之内必须动手。明路用追问式对话把案情结构化，围绕时间、金额、证据、对方说法四个要素逐条问清；再通过混合检索找到真正适用的条文；最终输出包含一句话结论、涉及法律、我的权益、对方可能存在的问题、建议准备证据、带时限的办理路线图、承办部门、可生成文书与风险提示的 11 章案件报告，并支持按已收集的事实起草催告函、律师函、投诉书、起诉状、答辩状、仲裁申请书、证据清单等文书。系统当前实现 8 类案由、101 个接口路径、134 个接口操作、62 张数据表、22 个前端页面，源码约 2 万行；法条库收录 872 条法条、132 部法规、29 条最高人民法院指导案例。项目处于工程闭环已完成、真实用户验证尚未开始的阶段。

### 2. 创新点与技术优势（不少于 200 字）

**其一，检索全程可溯源。** 法条库以 pgvector 存储向量，向量召回与关键词召回双路并行，经 RRF 融合排序，并支持 rerank 精排，模型不可用时自动降级而不中断服务。报告中的涉及法律章节强制走检索，每条结论标注法规名称与条号，检索不到时直接输出暂未收录，不做推测。

**其二，三道防幻觉闸门，这是本项目的核心差异。** 报告的个性化分析由大模型生成，但被三处硬约束锁住：事实封闭，只允许使用用户已经陈述的事实，不得引入任何外部情节；法条封闭，只允许引用检索结果中真实存在的条文编号，引用越界整份输出判定作废；结构可校验，输出必须是约定的结构化字段，字段缺失即视为失败。三条闸门任一不通过，系统自动回退到规则模板，报告永不空白。

**其三，两段式报告生成。** 模板段保证 11 章结构稳定、法律常识不出错；模型段负责个案化判断，包括本案权益、对方责任、风险与取证重点。两段在页面上分别标注生成来源，用户始终清楚哪一段是模型写的、哪一段是规则生成的，不做混同。

**其四，工程可验证。** 建立 99 项自动化测试，覆盖安全、检索融合、业务完整性、防幻觉与 API 契约，接入 GitHub Actions 持续集成；静态检查零告警；生产环境启动期自检弱密钥、默认数据库密码与 CORS 通配符，命中即拒绝启动。

### 3. 商业价值分析（不少于 200 字）

**需求侧。** 法律服务资源高度集中，普通人遇到小额高频纠纷时，律师费常常高于争议标的本身，大量纠纷在不知道该找谁的阶段就放弃了；社区法律服务点、工会职工服务站、律所与中小企业 HR 也缺少低成本的结构化初筛工具。明路切的是咨询服务之前那段空档：不替代律师，而是把用户送到对的门口，并把材料提前准备好。

**商业模式分三层。** 面向个人的订阅（单案包与月付，定价假设在 29 元每月量级，尚未经市场验证）；面向机构的授权（社区法律服务点、工会职工服务站、律所案源前置筛查、企业 HR 劳动关系初筛，按坐席或按年）；能力输出（法条检索与报告生成 API，按调用量计费）。单案成本主要由大模型调用构成，规则模板兜底可在模型不可用时把边际成本压到接近零。

**竞争位。** 市面上多数产品停在法条查询或法律问答，输出是一段解释；明路的输出是带承办部门与时限的路线图，以及可以直接拿去用的文书，差异在可执行而不在专业。护城河来自法条库质量、检索与引用校验流程、以及报告模板背后沉淀的办事流程，不在模型本身。

**前提与风险。** 法条库需扩容至全量并建立时效更新机制；法律专业内容需外执业律师按次审阅；定价与付费意愿必须靠试点验证。以上均属未完成事项，不作提前美化。

### 4. 应用场景及成效（不少于 200 字）

**典型场景。** 建筑工人被拖欠工资，不清楚该去劳动监察投诉还是申请仲裁；租客退租被扣押金，不知道举证责任在谁；网购到假货，不清楚惩罚性赔偿的适用条件；工伤之后未及时申请认定，临近时效；就医过程出现争议，需要判断是否构成医疗损害；亲友间借款仅有转账记录、没有借条；快递丢失或被冒领，赔付标准不明；以及婚姻家事中的财产与子女问题。以上 8 类案由，系统均已内置追问脚本、证据清单、承办部门与对应文书模板。

**服务形态。** 既可面向个人直接使用，也可作为社区法律服务点、街道司法所、工会职工服务站、律所案源前置筛查、中小企业劳动争议初筛的工作台，把接待、记录、初筛、转介这一段标准化。

**成效说明真实现状。** 项目已完成端到端工程闭环，8 类案由的报告、路线图与文书生成链路均可跑通；建立 99 项自动化测试并接入 CI；前端构建与后端接口全部通过；法条检索、引用校验、模板兜底三条链路均有回归测试覆盖。但必须说明：目前尚无对外用户量与办案结果数据，法条库为 872 条演示规模，检索召回率尚无标注样本支撑。下一阶段计划以 30 份真实案情样本评测报告准确率，并招募 10 位社区或工会一线人员做可用性试点，用可核验的数据替换现阶段的定性描述。

当前最迫切的是场景与业务合作两类需求。场景方面，希望对接社区法律服务点、街道司法所、工会职工服务站、劳动监察窗口、律所和中小企业 HR 等真实使用场景，用一线接待流程检验追问脚本与报告模板是否贴合实际，因为法律服务的难点往往不在法条，而在用户说不清楚、材料备不齐。业务合作方面，希望找到能共同打磨产品的合作方，包括律所案源前置筛查、法律科技服务商、职业院校与人力资源服务机构。创业辅导方面，最需要的是三件事：法条库全量接入的合规边界在哪里、法律专业内容的外协审阅机制怎么建、面向个人用户的产品定价与增长路径怎么走。产业对接方面，希望接触法律科技、公共法律服务、人力资源服务与企业合规领域的产业方与投资机构。场地方面，若进入试点阶段，希望在社区或园区获得一处可落地的服务点位用于线下验证。
