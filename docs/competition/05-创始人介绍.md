> 凡涉及创业细节与做法律方向的真实起因，均以【】标出，需替换为真实情况后再提交，不要原样保留。

## 一、短版（约 280 字，适合小输入框）

曹俊，计算机应用专业，明路（LawPilot）的发起人与唯一开发者。具备从数据库设计、后端接口、检索与排序、到前端交互的全栈实现能力，明路当前的 8 类案由办理流程、混合检索与引用校验、报告生成引擎、22 个前端页面，均由本人独立设计与实现。此前有一次创业经历，完整走过从发现需求、组织协作、做出可交付产品到面对真实客户的闭环，也因此形成两个判断：产品能否活下去，取决于它是否真的解决了某个具体的人的麻烦，而不是技术是否新颖；小团队最稀缺的资源是时间，所以明路从一开始就把工程可验证性放在前面，用 99 项自动化测试、持续集成流水线与生产启动自检，让一个人也能守住质量底线。选择法律这个方向，源于【此处填写真实起因，一两句即可】。

## 二、长版（约 680 字，适合「团队介绍 / 创始人故事」大输入框）

**基本情况。** 曹俊，计算机应用专业，明路（LawPilot）发起人，目前是该项目的唯一开发者与产品负责人。

**技术能力。** 计算机应用专业的训练给了我两样东西：一是把问题拆到数据结构层面的习惯，二是不依赖分工、自己把一件事从头做到尾的能力。明路是一个前后端一体的系统，包含 101 个接口路径、134 个接口操作、62 张数据表与 22 个前端页面，法条检索采用向量与关键词双路召回、RRF 融合排序并支持精排降级，报告生成则用两段式结构把模板段与模型段分开。这些模块从数据库建模、接口设计、检索逻辑到前端交互，均由本人独立完成。我不是在调用别人的能力拼装产品，而是清楚这套系统每一处为什么会这样写——这在做需要严格溯源的法律产品时，是最重要的底气。

**创业经历。** 此前我完整经历过一次创业。【此处替换：做了什么事 / 面向谁 / 持续多久 / 团队几人 / 我当时承担的角色 / 结果是继续、转型还是结束】。这段经历给我最大的收获不是方法，而是两个清醒的认知：其一，任何产品真正的对手不是同行，是用户「算了，不折腾了」的那一瞬间，所以必须把用户迈出第一步的成本压到极低；其二，资源有限时，能救命的只有聚焦，砍掉一切不能直接换来用户信任的功能。这两条直接决定了明路的形态——不做通用法律问答，只做「把一段混乱的纠纷说清楚，然后告诉你下一步找谁」这一件事，并且把「检索不到就说暂未收录」写进产品逻辑里，宁可承认不知道，也不猜。

**为什么做法律。** 【此处填写真实起因，建议写一件具体的事：自己或身边人遇到过的纠纷、跑过的窗口、吃过的亏。一两句具体的细节，比任何宏大理由都有说服力。】

**做事方式。** 我相信可验证胜过可描述。明路建立了 99 项自动化测试，覆盖安全、检索融合、业务完整性、防幻觉与接口契约，接入持续集成；静态检查保持零告警；生产环境启动时会自检弱密钥、默认数据库密码与跨域通配符，命中即拒绝启动。这些工作在演示时看不见，但它们决定了一个法律产品能不能被信任。

## 三、创业经历的可替换写法（按真实情况选一段）

**A. 如果是技术型创业（软件外包 / 工作室 / 做过交付项目）**

此前我与几位同伴组建过一个小型技术团队，承接【行业】的软件交付项目，我负责【需求沟通 / 方案设计 / 核心开发】。这段经历让我第一次直面「需求方说的」与「需求方真正要的」之间的差距，也让我习惯了在预算与工期都紧的情况下做取舍。后来因为【原因】没有再继续。

**B. 如果是产品型创业（做过 App / 小程序 / SaaS）**

此前我参与创办【产品名或方向】，面向【目标用户】提供【核心价值】，我主要负责【产品设计与开发 / 整体推进】。产品上线后【拿到多少用户 / 多少付费 / 什么反馈】。最终因为【原因】停止。这次经历让我明白，做出一个能跑的东西只是起点，让人愿意持续用才是真正的难题，而后者跟技术能力几乎无关。

**C. 如果是校园或本地服务型创业（工作室 / 校园服务 / 本地商家服务）**

此前我在校内（或本地）做过【具体业务】，服务【客户类型】，高峰期【规模数字】。我负责【角色】。这段经历让我学到的最实用的一课，是如何用最小的成本验证一个需求是不是真的存在——先收钱，再干活，比先做产品再找客户可靠得多。

## 四、提交前必须补齐的信息

以下七项我无法代填，填错会在答辩现场被追问：

1. 创业做的是什么（行业、产品形态）
2. 时间跨度（哪一年到哪一年）
3. 团队规模与你承担的角色
4. 结果：还在继续 / 已结束 / 转型，结束的原因
5. 有没有真实付费客户与大致金额（可只写量级）
6. 做法律方向的真实起因（一件具体的事最好）
7. 是否需要补充合作者：目前是单人项目，若有法学背景或执业律师参与审阅，务必写进去——这是评委最会追问的一点

## 五、使用提醒

- 短版与长版都**不要同时提交**，看表单框大小选一个。
- 「唯一开发者」这个表述建议保留。单人完成一个 2 万行、101 个接口的系统，本身就是一人公司赛道最有力的证明，不必掩饰团队小。
- 若表单另有「是否已有营业执照 / 公司主体」字段，请按实际情况填，不确定的先不填，不要写「拟成立」以外的模糊说法。
