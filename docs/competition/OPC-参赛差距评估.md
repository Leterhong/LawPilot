## 一、结论先行

**LawPilot 的工程体量与功能完整度已明显超出学生作品平均水平，具备参赛资格；但按 OPC 系列赛事的评审口径，"能跑通并产生价值"这一条目前无法自证。**

差距不在代码量，而在**可验证性**：没有测试、没有 CI、没有在线 Demo、没有评测数据、没有用户验证材料。评委无法仅凭仓库判断这个系统是否真的能运行。

本次已完成 4 项硬修复与 1 项核心能力升级（详见第五节），把项目从「看起来能跑」推进到「有证据证明能跑」。剩余缺口需要外部条件（模型密钥、部署环境、真实用户），列在第六节。

**判断：完成第六节的 P0 项后，可达到 OPC 自由赛道一等奖竞争水平。**

### 共性评审维度

| 维度 | 评委要什么 | 对应交付物 |
| --- | --- | --- |
| 问题真实性 | 谁需要、为什么需要、有无真实痛点证据 | One Pager、用户访谈记录 |
| AI 承担核心作用 | AI 不是包装，而是能力主体 | AI 使用说明、Prompt 与链路说明 |

| 落地潜力 | 商业模式、可推广性 | 路演 Deck、成本测算 |

LawPilot 的问题选择（普通人不会打官司、不懂维权路径）在"社会价值"与"问题真实性"两项上天然占优——这是法律 AI 相对通用聊天机器人的结构性优势，应当在材料中前置放大。

### 功能模块

智能维权 Agent、法规检索、案例检索、案件中心、合同智能审查、证据中心（OCR / 证据链 / 时间线 / 报告）、法律研究、AI 能力中心（Provider / 模型 / 路由 / Prompt / Token 统计）、AI Playground（单测 / 对比 / 评测 / 路由测试）、账户体系。

### 技术亮点（可用于答辩的技术差异化）

1. **混合检索**：pgvector 语义召回 + PG 全文检索，采用 RRF（倒数排名融合）合并，可挂 Rerank 精排，Embedding 服务不可用时自动降级为纯关键词检索。
2. **引用可溯源**：报告"涉及法律"章节强制走 RAG，每条条文带 `source_table` / `id` / `label` / `score`，可回链到知识库原始记录。
3. **AI 治理视角**：内置 AI 能力中心与 Playground，把模型选型、路由、Prompt 版本、Token 成本、健康检测纳入统一管理——这在同类学生作品中罕见，是很好的答辩点。
4. **三段式编排**：`docker-compose.yml`（基线）+ `.dev.yml` + `.prod.yml`，规避了 Compose 无法删除父文件端口的常见陷阱，说明作者理解编排语义而非套模板。

## 四、差距矩阵

评分采用 1-5 分制，5 分为"评委无需追问即可采信"。

| 维度 | 升级前 | 升级后 | 主要缺口 |
| --- | --- | --- | --- |
| 问题真实性 | 4 | 4 | 缺少真实用户访谈 / 使用数据 |
| AI 承担核心作用 | **2** | **4** | 原报告为静态模板，个案事实未进入正文 |
| 可跑通、可验证 | **1** | **3.5** | 无在线 Demo，无端到端评测数据 |
| 创新性 | 3.5 | 4 | 需在材料中明确"工作流"而非"问答"的定位差异 |
| 社会价值 | 4.5 | 4.5 | 材料未论证 |
| 落地潜力 | 2.5 | 2.5 | 无商业模式与成本测算 |

### 关键差距详解

#### 差距 1：AI 其实是"装饰"（已修复）

**原状**：`report.py` 的 11 章节中，除"涉及法律"走 RAG 外，结论、权益、对方问题、风险四项全部来自 `knowledge_base.py` 的硬编码字典，按 `case_type` 查表返回。

后果：同为"拖欠工资"，无论用户陈述什么都拿到完全相同的分析；用户亲口提供的金额、时间、证据、对方说法，一个字都没进入报告。

这是**答辩致命伤**——评委问"AI 在这里做了什么"，只能回答"检索法条"。而 Demo 一演示，模板痕迹一眼可见。

**已修复**：新增 `app/services/agent/llm_report.py`，把逐条追问收集到的事实与 RAG 法条一起送入模型，生成个性化分析，并用三道闸门约束幻觉：

| 闸门 | 机制 | 违反后果 |
| --- | --- | --- |
| 事实封闭 | 只允许使用 `collected_fields` 中的用户陈述 | Prompt 硬约束 |
| 法条封闭 | 只能引用传入的编号（`【法条N】`） | 越界即整段作废 |
| 结构可校验 | 强制 JSON + 五字段非空 + 字数上限 | 不合规即回退 |

任一道闸门不通过，自动回退到原模板，报告不会降级为空白。此路径已有 13 项自动化测试覆盖。

#### 差距 2：无法自证能跑通（部分修复）

**原状**：`backend/tests/` 只有一个 `__init__.py`，但 `Makefile` 里有 `make test`，README 里写着"运行后端测试"。这是**空承诺**，一旦评委实际执行就会暴露。

**已修复**：建立 99 项测试，覆盖 JWT 安全、配置自检、RRF 融合、引用构造、8 类案由完整性、报告渲染、防幻觉闸门、OpenAPI 契约。全部不依赖数据库与密钥，CI 中秒级完成。

**仍缺**：端到端集成测试（需 PostgreSQL）、在线可访问的 Demo 地址。

#### 差距 3：文档只讲"有什么"，不讲"为什么"

README 是功能清单，缺少：目标用户画像、与现有法律服务的差异、典型用户旅程、效果数据。参赛材料的这三块需要重写，不是补充。

#### 差距 4：工程细节的"可信度税"

评审若细看代码，会发现若干降低可信度的问题。已修复的列在第五节；未修复的列在第六节 P2。

## 五、本次已完成的升级

### A. 确定性缺陷修复（3 项，均为运行时崩溃级）

| 位置 | 问题 | 影响 |
| --- | --- | --- |
| `playground/router.py` | 路由函数 `create_prompt` 覆盖同名导入，函数体内调用自身 | `POST /api/playground/prompts` 无限递归 → 500 |
| `playground/router.py` | `EvaluationTask` / `EvaluationResult` 未导入 | `GET /api/playground/evaluations` NameError → 500 |
| `main.py` | `custom_openapi` 未传 `tags` 参数 | /docs 分组描述全部丢失（18 组标签仅剩 0） |

### B. 静默失效修复

`ai/manager.py` 的 rerank 方法中构造了一个 OpenAI 客户端对象但从未使用（实际走 `httpx`），已移除。不属功能缺陷，但属于评审扣分的低级问题。

### C. 依赖配置矛盾

`pyproject.toml` 声明 `bcrypt>=4.1.0,<4.2`，而 `requirements.txt` 为 `<4.1` 并附注释说明 4.1+ 与 passlib 1.7.4 不兼容。**按 pyproject 安装会导致注册/登录 500**。已统一为 `<4.1`。

### D. 核心能力升级：AI 真正参与报告生成

见"差距 1"。改动文件：

- 新增 `backend/app/services/agent/llm_report.py`（个性化分析与三道闸门）
- 修改 `backend/app/services/agent/report.py`（两段式生成，报告新增 `facts` 与 `meta`）
- 修改 `backend/app/services/agent/engine.py`（向报告引擎传递 `workflow`）
- 修改 `frontend/src/lib/api.ts`、`frontend/src/app/cases/[id]/page.tsx`（展示生成来源、事实梳理、法条引用标注）

报告新增字段：

```json
{
  "facts": ["- 是否签订了书面租赁合同 → 签订了", "..."],
  "meta": {
    "analysis_source": "llm",
    "fallback_reason": "",
    "cited_articles": [1, 2],
    "fact_count": 5,
    "citation_count": 8
  }
}
```

前端在报告页顶部显示「AI 个性化分析 / 规则模板生成」标识，并标注哪几条法条被实际引用。**这一处改动直接回应"AI 是否承担核心作用"的质疑，且可在 Demo 中当场演示。**

### E. 安全加固

- 生产环境启动期自检：默认密钥、短密钥、默认数据库密码、CORS 通配符，任一命中即拒绝启动
- 生产环境默认关闭 `/docs`、`/redoc`、`/openapi.json`（可用 `EXPOSE_DOCS=true` 显式开启）
- 移除 134 项静态问题（未使用导入、导入排序），ruff 全绿

### F. 工程基线

- 新增 `.github/workflows/ci.yml`：后端规范与测试、前端类型与构建、三套 Compose 配置校验
- 新增 `tests/` 下 6 个测试文件、99 个用例

## 七、风险提示

1. **法律合规**：产品提供法律信息参考，不构成法律意见。免责声明已覆盖，但若对外公测，建议核查《互联网信息服务深度合成管理规定》相关要求，并对 AI 生成内容做显著标识（本系统已在报告页标注生成方式，可作为合规依据）。
2. **数据权威性**：872 条法条为手工整理的种子数据，不可声称"覆盖全部法律"。答辩时应表述为"演示用知识库，生产环境需对接权威数据源"。
3. **赛事选择**：三个 OPC 赛事的赛道、材料、评审权重不同，珠海赛要求"截至 2026-09-30 登记注册未满 5 年的自然人独资/控股公司"，在校学生需核对是否符合。**建议先定赛事再写材料，避免返工。**
